# sync/web – la page de House Sync

Projet Vite + React + TypeScript à part (mêmes conventions que le site : un dossier par composant, Tailwind, alias `@/`, TypeScript strict, ESLint). Compilé dans l'image de House Sync, servi par lui sur le port 8081. Le rendu vient du paquet **`@house/ui`** (`../../ui`) : ici ne restent que les conteneurs.

- `lib/api.ts` : les services de House Sync (connexion, vue d’ensemble, tables, clips, réglages, machine, Docker, réseau, Hue), session par cookie.
- `components/App` : la clé, puis cinq onglets (`Base`, `Disque`, `Machine`, `Docker`, `Réglages`), **Base** (les tables de la base, paginées), **Disque** (la liste des clips du disque backup, rien d'autre), **Machine** (caractéristiques `SpecList`, réseau (le câble RJ45 et le WiFi : connecté ou non, débit, signal, trafic), pont Hue (joignable ou non, au même niveau que le réseau, seulement si une adresse de pont est réglée), **Adresses IP de la maison** (un tableau HTML à trois colonnes **Adresse / Matériel / Port**, écrit à la main dans `App/constants.ts`, `ADDRESS_ROWS`, avec `SimpleTable` de `@house/ui` : la box, le mini PC, le switch, les deux caméras, le pont Hue, la prise Kasa, les réseaux de la maison, du VPN et de Docker, l’IP publique et son nom Free ; à tenir à jour quand une adresse change), courbes en direct `LineChart` relues toutes les 2 s, camemberts mémoire, processeur et disque, consommation : processeur, caméras PoE, total mesuré) **Docker** (une fiche par conteneur) et **Réglages** (tous les réglages de House Sync, voir `SettingsSection`) ; tous les blocs se replient (`Collapsible` de `@house/ui`), les « Caractéristiques » le sont au départ ; **seule la page affichée est chargée** (`loadTab` dans `App.tsx` : Base et Disque lisent la vue d'ensemble **sans parcourir le disque backup** (`GET /api/overview?part=database`), Machine lit aussi le disque, la puissance, le processeur, les caractéristiques, le réseau et le pont Hue, Docker ne lit que Docker, Réglages se lisent eux-mêmes) ; les autres pages se chargent par leurs propres requêtes quand on les ouvre, et toutes les 15 s seule la page affichée est relue (sauf média ouvert) ; un compteur `refreshTick` fait recharger leur page aux tableaux.
- `TableSection` : une table de la base, **avec ses filtres** (`TableFilters` de `@house/ui` : caméra et date pour `events`, `snapshots`, `merges` ; nom du matériel et date pour `hue_events` ; date seule pour `guest_visits` ; une requête refaite à chaque choix, `lib/filter.ts`), les horodatages sur deux lignes (`StackedDate`), paginée (20 lignes) et **repliée par défaut, toutes les tables** (le titre déplie ; la page n'est chargée qu'une fois dépliée), une description par table dans `constants.ts` (`DESCRIPTIONS`) ; le rendu des cellules est dans `UI.tsx` (clip ou image → bouton « voir », adresse → lien, horodatage → date, étiquette → pastille, adresse IP → en une ligne, jamais coupée) ; **`guest_visits` n'affiche que ses colonnes principales** (`MAIN_COLUMNS`, dans cet ordre : `id`, `started_at`, `ip`, `origin`, `cle` (**avec clé / sans clé / clé fausse**), `camera`, `path`) et **le reste au clic sur la ligne** (le détail sous la ligne : fin, type, navigateur, qualité, statut, durée, octets, langue, hôte, User-Agent), grâce aux lignes dépliables du `DataTable` de `@house/ui`.
- Onglet Machine, « Processeur par thread » : repliée par défaut, une petite courbe en direct par thread (`cpu.perThread`, relu toutes les 2 s, 2 minutes d'historique), sous les courbes du processeur et de la mémoire.
- `SettingsSection` : l'onglet **Réglages**, **tous** les réglages de House Sync, rangés **par sujet** (un bloc repliable chacun, une ligne par caméra quand le réglage est par caméra, chaque clic ou curseur relâché est enregistré tout de suite, un échec s'affiche) : **Enregistrement : clips et images** (la durée de garde des clips non sauvegardés, 7 à 180 jours, `GET`/`PUT /api/retention` ; par caméra, **Toujours / La nuit / Jamais** : hors des clips gardés la détection de la caméra est éteinte ; et le rythme des images de la frise, **30 s, 1, 2 ou 5 min**), **Détection du mouvement** (un curseur « Sensibilité du mouvement » de 1 à 5 par caméra ; sert quand une caméra rate un passage), **Direct dans la WebApp** (quatre curseurs par caméra, « Direct 4K » et « Direct léger », chacun pour le PC (1024 px et plus) et pour le téléphone, de 1 à 25 images par seconde, envoyés au relâchement seulement si la valeur a changé) et **Page invité** (un seul curseur, 1 à 25 images par seconde, pour les vignettes et la caméra agrandie en 4K, PC et téléphone confondus, `GET`/`PUT /api/guest`).
- `ClipsSection` : les clips du disque backup en **une seule table, deux vues** (onglets « Sauvegardés » / « Les autres », filtres caméra et date), paginés, **une ligne par événement** avec ses deux versions (copie légère H.264 720p et original H.265 4K, un bouton « voir » et la taille de chacune ; `/api/clips` réunit les fichiers `<id>.h264.mp4` et `<id>.mp4` avec `groupClips`).
- `MediaPanel` : le clip ou l'image ouvert, dans le panneau collant de `@house/ui` au-dessus des tableaux ; la vidéo démarre à l'ouverture, Fermer l'arrête, les tableaux ne changent pas de taille.

Développement : `npm install`, `npm run dev` (HTTPS sur 5181 avec le certificat de `data/certs`, services relayés vers House Sync). Vérifications : `npm run typecheck && npm run lint && npm run build`.
